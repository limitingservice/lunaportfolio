Most listings name maybe one of those. This one frames the whole intern as someone who designs in components, ships into code, and thinks fluently in AI-assisted workflows. That's the conversation I've been having through my own work for the last two years.

The strongest direct parallel from my recent portfolio is a browser-based augmented reality virtual try-on for eyewear that I designed and built end-to-end against an e-commerce conversion problem — online eyewear has a 30–50% return rate driven primarily by "didn't look right on me." The design surface covered a 9-screen user journey, a 5-state interaction pattern (camera permission → face acquisition → tracking lock → live try-on → recovery on lost tracking), and a privacy-first consent flow tuned to push permission acceptance from ~40% to ~85%. I shipped the visuals in Figma and then built the production version in React, Three.js, and MediaPipe — which means I've lived with both sides of the design-engineering handoff and felt the cost of every interaction decision in code, not just in mockups. That same project is also where I started designing reusable interaction patterns (the 5-state machine, the inline color-switching control, the permission-then-acquisition-then-tracking flow) that I'd now build as proper system components — which is where this role's design-system focus is going to land for me.

On the AI-in-design side, my portfolio site itself is a working case study. I built it on Cursor and Google Antigravity, deliberately experimenting across the full model stack — Gemini 3.1 Pro High, Claude Opus, Claude Sonnet, and the lighter tiers — at very different intensities. Partly to ship features fast (interactive 3D viewers for each project, including a procedural smart cane model with floating feature annotations). Partly to map out where each model actually earns its place in a real design workflow. My honest take on AI-assisted design: the biggest win isn't raw speed. It's that AI lets you fail faster, iterate faster, hit the next milestone faster, and surface the gaps in your own workflow that weren't visible before — where automation actually does the work, where it only looks like it does, and where you still need human presence and real research to land on user needs that hold up.

Multi-platform, multi-stakeholder, multi-device — which is the kind of complexity a scalable component system has to absorb without buckling.
